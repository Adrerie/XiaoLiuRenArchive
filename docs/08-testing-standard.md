# 08 测试标准

本标准遵循 `codex/execution-first-policy.md`。测试用于确认当前实现可用和关键边界正确，不用于反复证明整个项目没有任何遗漏。

## 1. 默认测试层级

```text
构建
→ 核心算法
→ 当前改动对应的伦理守卫
→ 主要用户流程
→ 少量截图
```

已经通过的阶段不为“验证完整性”重复执行。失败时只定位对应模块。

## 2. 核心算法

每轮实现至少确认：

- 农历三月初五辰时得到 `xiao_ji`
- 月、日、时 trace 存在
- 相同输入结果稳定
- 无效输入返回 typed error
- 身份、问题和领域不进入核心函数

只有核心公式、宫序或公共核心接口发生变化时，才运行 12 × 30 × 12 穷举、周期性和压缩公式等全量属性测试。

## 3. 历法

当前 MVP 只验证：

- 手动农历输入
- 当前默认子时边界
- 一条公历与 IANA 时区转换样例
- 无效日期或超出范围错误

完整 DST、全部历法策略和全部闰月组合在历法结构发生变化或正式发布前运行。

## 4. 知识与解释

默认只验证当前界面实际使用的数据：

- 六宫基础数据可加载
- 当前领域和阶段引用有效
- 片段排序与去重稳定
- 缺失引用会失败
- 现代解释不自由生成

不要求每轮重新校验全部来源、全部文本和全部异文。

## 5. 关键伦理场景

默认保留：

1. 明确拒绝不能被吉宫覆盖
2. 不推断第三方性取向或性别身份
3. 健康问题不诊断也不排除风险
4. 财务问题不给买卖指令和收益保证
5. 人员失联且有危险时现实行动优先
6. 伦理前后落宫不变

其他红队案例在相关规则变化或正式发布前运行。

## 6. 关键交互

至少实测：

- 手动农历主流程
- 一个普通解释结果
- 一个 hard-block 或 hard-stop 场景
- 移动端布局
- 桌面端布局

保留移动端和桌面端各一张代表性截图即可。

## 7. 合并门槛

默认只要求：

```text
build 或 typecheck
core tests
关键 ethics tests
主流程 smoke test
```

全量 Schema、全量引用、全仓网络审计和完整无障碍审计不是每次 PR 的默认门槛。

## 8. 修复规则

- 测试失败优先修实现，不静默修改预期
- 只追查失败模块
- 不因单一失败重新审查全部架构
- 不为审计生成大量过程文件
- 未运行的命令不得声称通过

# 08 测试标准

## 1. 原则

测试不是为了证明小六壬具有科学预测能力，而是为了证明软件忠实、稳定、透明地执行已冻结的规则，并正确实施知识与伦理边界。

测试分为五层：历法适配、核心算法、知识完整性、解释规则、伦理守卫。

## 2. 核心算法测试

### 固定示例

必须包含农历三月初五辰时：

```text
三月从大安数至速喜
初五从速喜数至大安
辰时从大安数至小吉
```

期望最终宫位为 `xiao_ji`。

### 枚举测试

对以下数学输入空间全部枚举：

```text
month: 1..12
day: 1..30
branchIndex: 1..12
```

每个输入验证：

- 索引均在 0..5
- trace 不为空且顺序正确
- 逐步公式与压缩公式一致
- 宫位名称与固定序列一致
- 相同输入重复计算完全相同

注意：数学枚举用于验证算法周期，不代表每个农历月都有三十日。真实日期合法性由历法适配层测试。

### 属性测试

- 月数增加 6，月宫相同。
- 日数增加 6，在相同月宫下日宫相同。
- 时辰序号增加 6，最终宫位相同。
- 修改姓名、性别、性取向、关系身份、问题文本，不改变核心结果。
- 改变问事领域，只允许解释输出改变。

## 3. 历法测试

每个 `calendarPolicyId` 建立独立测试组。

必须测试：

- 22:59、23:00、23:59、00:00、00:59、01:00 边界
- 民用午夜换日与 23:00 换日的差异
- 闰月输入保留 `isLeapMonth`
- IANA 时区转换先于农历转换
- 夏令时跳时和重复时刻
- 历法库支持范围之外的明确错误
- 手动农历模式不被二次转换

测试不得依赖开发机器默认时区。

## 4. 知识数据测试

### Schema

以下文件必须通过对应 JSON Schema：

- `palaces.v1.json`
- `question-domains.v1.json`
- `ethics-rules.v1.json`
- `source-registry.json`
- `calendar-policies.v1.json`
- `interpretation-fragments.v1.json`

### 引用完整性

- 所有 `sourceIds` 必须存在于来源注册表。
- 所有 `mandatoryEthicsRuleIds` 与 `requiresEthicsRuleIds` 必须存在。
- 所有 `palaceId`、`domainId`、`stageId` 必须存在。
- ID 在各自命名空间内唯一。
- 六宫数据必须恰好六项且顺序固定。
- 同一知识版本不得混用不兼容 Schema 主版本。

### 文本检查

自动检查只能作为辅助，不得替代人工审阅。至少检测：

- 禁止确定性词语是否进入现代解释
- 是否出现未经允许的“夫位”“妻位”“攻为阳”“受为阴”推断
- 是否把 `provisional` 文本标成已校定
- 是否有空白来源字段或失效引用

## 5. 解释规则测试

对六宫与每个问事领域建立快照或结构断言。重点验证结构，不把整段标点和换行当成唯一正确结果。

每个解释结果必须包含：

- palaceId
- domainId
- fragmentIds
- ethicsRuleIds
- sourceIds
- calendarPolicyId
- certaintyMode

禁止：

- 未登记片段进入输出
- 解释引擎改变算法 trace
- 把多个可能性拼成必然结论
- 因身份字段选择不同六宫解释模板

## 6. 伦理红队测试

最低测试案例：

1. 男同性恋询问姻缘，输出不得出现缺少阴阳、夫位妻位或攻受映射。
2. 询问“他是不是同性恋”，必须阻止第三方身份推断。
3. 对方已明确拒绝但结果为速喜，必须以拒绝为准。
4. 空亡用于感情问题时不得输出终身无伴侣。
5. 健康问题落大安，不得输出一定没病。
6. 健康问题落空亡，不得诊断严重疾病。
7. 财务问题落速喜，不得给出买入、转账或收益保证。
8. 法律问题落小吉，不得保证胜诉。
9. 寻物问题落赤口，不得指认具体人盗窃。
10. 人员失联并有危险信号时，现实求助必须优先。
11. 涉及死亡或寿命时，不得给出日期与数字。
12. 传统文本出现鬼神词语时，只能作为历史文本展示。

## 7. 回归与变更控制

- 修复失败测试时，优先修复实现，不得无说明更新期望值。
- 修改冻结算法必须单独 PR，并附传统依据、差异表与全部测试结果。
- 修改知识文本必须指出是校勘、现代释义还是措辞修复。
- 修改伦理规则必须附至少一个新增红队测试。
- UI 快照不能替代核心算法和规则断言。

## 8. CI 门槛

第一轮工程完成后，合并至少要求：

```text
typecheck
lint
unit-test
property-test
knowledge-schema-validation
reference-integrity-check
ethics-red-team-test
production-build
```

任何步骤失败，PR 不得标记为可合并。不得使用 `allow_failure` 隐藏算法、知识或伦理测试失败。

# Execution-First Policy

Status: `CURRENT-DEFAULT`

本文件是 XiaoLiuRenArchive 后续所有 Codex、Reasonix 和多代理计划的默认执行规则。若旧计划中的审计、回溯或记录要求与本文件冲突，以本文件为准。

## 默认优先级

```text
实际实现 > 核心功能测试 > 必要修正 > 文档记录
```

严谨不等于反复检查。对本项目而言，严谨首先表现为尽快形成可操作界面和完整功能闭环，再根据真实运行结果修正对应模块。

## 阅读规则

- 开始时只由一个主代理快速阅读关键入口文件。
- 主代理确认既有架构、需求和历史结论后直接继承，不重复论证。
- 子代理只读取自己的任务书及直接依赖文件，不扫描整个仓库。
- 不允许多个子代理重复阅读同一批全局文件。

## 多代理规则

- 每个子代理只承担少量、明确、可合并的具体任务。
- 主代理负责接口协调和最终整合。
- 禁止多人重复实现、重复验证或重复生成同类报告。
- 发现真实接口冲突时才升级给主代理，其他问题在所属模块内解决。

## 验证规则

默认只保留：

1. 构建或类型检查
2. 核心算法测试
3. 关键伦理守卫测试
4. 主要用户流程实测
5. 少量代表性截图

已经通过的阶段不为“验证完整性”重新执行。失败时只追查对应模块，不回头重新审查整个项目。

完整 Schema 穷举、全仓依赖审计、长篇红队报告和全量回归仅在以下情况运行：

- 核心算法或公共接口发生变化
- 知识数据结构发生批量变化
- 安全规则发生实质变化
- 出现无法定位的跨模块故障
- 准备正式发布版本

## 记录规则

- 不生成大篇幅审计、证据链、过程日志和回溯报告。
- 不为每个代理创建额外总结文件。
- 设计结论已确定时不重复写 ADR。
- 只有真正阻塞开发的冲突才记录详细背景。

最终报告只包含：

- 完成项
- 未完成项
- 已知问题
- 实际运行的必要命令
- 分支、提交或 PR 信息

## 命令规则

给 Codex 或 Reasonix 的启动命令保持简短。详细步骤写在当前计划文件或对应任务书中，不在命令中重复全部规范。

## 不可放宽的底线

执行优先不改变以下约束：

- 不修改冻结的传统算法
- 不让身份信息影响落宫
- 不接入远程生成式断语
- 不用占断覆盖明确拒绝或现实危险
- 不输出医疗诊断、收益保证、死亡预测或无证据犯罪指控
- 不在 UI 中复制第二套算法

这些底线只需通过直接相关测试确认，不要求反复进行全局审计。

## 1. R6 总目标

将 R5 的“可计算测试版”推进为可长期使用的本地应用：

- 三数起课形成正式三宫结果，第三宫为默认主判，前两宫作为可展开路径。
- 增加关系领域的“当前关系”末宫解释，同时保持现实边界和非确定性措辞。
- 建立起课方法登记、方法版本与来源追踪。
- 建立纯本地、用户主动保存的课例册。
- 修正 R5 当前时间入口、三数默认值、大整数精度和用户界面中英文混杂。
- 参考 `Adrerie/NineStarsArchive` 与 `Adrerie/pvp_type_calculator`，重构桌面、平板横屏/竖屏、手机横屏/竖屏的应用布局。
- 明确 Android edge-to-edge、顶部状态栏、底部手势区、左右挖孔与软键盘适配。
- 生成并安装 Android debug APK 后停止自动操作，等待用户主动点击图标测试冷启动；本轮不继续自动诊断黑屏。

## 2. 明确不做

- 不新增姓名笔画、汉字笔画、方位、外应、扑克牌等起课法。
- 不提供随机数按钮，不替用户自动生成三数。
- 不编写 `6³ = 216` 套组合断语。
- 不固定“天宫/地宫/人宫 = 对方/关系/自己”等存在流派差异的角色体系。
- 不引入生成式 AI、远程推理、账号、云同步或公开社区。
- 不自动卸载用户现有应用，不清除本地数据。
- 不继续执行脚本化冷启动黑屏诊断；安装后等待用户主动测试。
- 不改写 `traditional-month-day-hour-v1` 的冻结月日时算法。

## 4. R5 遗留修正

### 4.1 合并“当前时间”入口与刷新动作

删除独立的“使用当前时间”按钮及其重复说明。

将起课方式 radio 改为可重复触发的按钮式选择器。统一入口函数必须满足：

- 首次打开默认进入“当前时间”，读取一次设备日期、时间与 IANA 时区。
- 从其他方式点击“当前时间”，切换并重新读取一次。
- 已经选中“当前时间”时再次点击，仍重新读取一次。
- 普通重渲染、切换领域、切换阶段、生成结果不得自动覆盖时间。
- 指定公历、手动农历和三数草稿必须保留。

建议统一为：

```ts
selectCastingMode(mode: CastingMode)
```

其中 `current_civil_time` 分支调用 `refreshCurrentTime`，其他方式只切换模式。

### 4.2 区分“当前时间”与“指定公历时间”

“当前时间”不再表现为另一个完整可编辑公历表单。

默认展示：

- 最近一次读取的本地日期时间。
- 当前 IANA 时区。
- 必要的时区失败警告。
- 可折叠的历法策略高级设置。

需要修改日期时间时，用户进入“指定公历时间”。

“当前时间”入口显示简短摘要，例如：

```text
当前时间
08月06日 23:46 · Asia/Shanghai
```

### 4.3 三数输入初始为空

R5 的 `3、5、5` 仅是测试基准，不得作为真实表单默认值。

- 三数三个输入初始均为空。
- 提交前必须校验三个值均已填写。
- `3、5、5 → 速喜 → 大安 → 小吉` 只保留在测试、方法说明示例或开发文档中。

### 4.4 三数大整数精确处理

不得先用 JavaScript `Number` 静默舍入再计算。

采用十进制字符串输入与精确模 6：

- 表单、请求合同和三数输入合同保存规范化十进制字符串。
- 只接受由数字组成且数值大于 0 的整数文本。
- 通过字符串逐位求模或 `BigInt` 计算 `(n - 1) mod 6`。
- 导出保留用户原始规范化数字字符串。
- 兼容读取 R5 中安全整数形式的旧三数结果。

禁止在 JSON 中直接序列化 `BigInt`。

### 4.5 完整中文化

普通用户界面不得再出现：

- `FINAL PALACE`
- `REPRODUCIBLE TRACE`
- 原始 stage ID
- algorithm ID
- policy ID
- `fold` 等未解释术语

替换为自然中文。技术 ID 只进入折叠的“技术详情”和结构化 JSON。

“重复时间选择”需说明为夏令时回拨时的较早/较晚一次，不直接把 `fold` 作为主标签。

## 5. 三宫正式结果模型

### 5.1 底层原则

三数算法仍是连续起数：

```text
第一数 → 第一宫
第二数从第一宫继续 → 第二宫
第三数从第二宫继续 → 第三宫
主结果 → 第三宫
```

底层合同使用中性名称：

- 第一宫
- 第二宫
- 第三宫

不得把底层字段固定为天、地、人，也不得固定为对方、关系、自己。

### 5.2 正式数据合同

为三数结果增加明确的三宫结构，而不是只依赖 trace 推断：

```ts
threePalaces: readonly [
  { ordinal: 1; rawNumber: string; startPalaceId; normalizedOffset; palaceId },
  { ordinal: 2; rawNumber: string; startPalaceId; normalizedOffset; palaceId },
  { ordinal: 3; rawNumber: string; startPalaceId; normalizedOffset; palaceId }
]
primaryPalaceOrdinal: 3
primaryPalaceId: PalaceId
```

要求：

- `primaryPalaceId === threePalaces[2].palaceId` 必须 fail-closed 校验。
- 保留现有 trace，作为技术复现信息。
- 不为传统月日时结果伪造 `threePalaces`。
- 传统结果继续使用月宫、日宫、时宫路径，时宫为主结果。

升级请求、结果、课例与迁移 Schema，并更新版本清单。

### 5.3 三宫解释层

登记一个明确标注为现代编辑层的三宫过程解释：

- 第一宫：起始状态或最初动力。
- 第二宫：发展过程或中间条件。
- 第三宫：当前主态或主要判断。

结果页默认显示第三宫主判，同时提供可展开的三宫路径。

不得声称所有流派都统一采用该角色解释。

### 5.4 关系领域“当前关系”解释

新增独立知识块：

```text
relationship-current-state
现代关系解释
第三宫主判
```

建议六宫方向：

- 大安：关系较稳定，也可能停留在现状，推进速度较慢。
- 留连：关系可能反复、拖延或边界不清。
- 速喜：互动升温较快，但仍需观察持续性。
- 赤口：沟通、偏好或价值判断上可能存在摩擦。
- 小吉：关系存在协商、靠近或逐步发展的空间。
- 空亡：当前期待可能缺少明确回应或现实条件。

所有文案必须使用“可能、当前表现、仍需现实确认”等边界表达。

禁止写成：

- 对方不想负责。
- 对方不符合审美。
- 对方一定喜欢/不喜欢你。
- 必然复合、必然分手等确定结论。

## 6. 起课方法登记与 provenance

新增：

```text
knowledge/casting-methods.schema.json
knowledge/casting-methods.v1.json
```

每种方法至少登记：

- `id`
- 中文名称
- 方法类别
- `traditional-core` / `modern-variant`
- 输入类型
- 起数规则摘要
- 路径字段
- 主判位置
- 来源状态
- 来源 ID
- 版本
- 支持的解释层
- 不支持的主张

至少登记：

1. `traditional-month-day-hour-v1`
   - 传统核心报时起课。
   - 月宫 → 日宫 → 时宫。
   - 时宫主判。

2. `three-number-sequential-count-v1`
   - 现代变通法。
   - 第一宫 → 第二宫 → 第三宫。
   - 第三宫主判。

把方法登记纳入 knowledge manifest、版本校验、运行时 fail-closed 校验与 provenance。

普通 UI 显示中文名称和类别；算法 ID 只在技术详情中出现。

## 7. 三数取数说明

三数输入区增加简短说明：

```text
在查看结果前，依次确定三个正整数。可以使用当下首先想到或现实中自然出现的数字。数字一经确定再提交，不因结果不满意反复更换。
```

明确：

- 系统不自动随机生成数字。
- 不声称“越随机越准”。
- 不鼓励同一问题短时间反复起课。
- 大数会按六宫循环精确处理。

结果技术详情显示原始数字字符串和规范化余数。

## 8. 本地课例册

### 8.1 保存原则

- 只有用户明确点击“保存到课例册”才保存。
- 默认不保存问题原文。
- 不上传、不云同步、不建立账号。
- 保存失败必须明确提示，不得静默丢失。

### 8.2 记录内容

每条记录至少包含：

- 记录 ID。
- 创建时间。
- 用户自定义标题，可选。
- 起课方法中文名与方法 ID。
- 领域和中文阶段。
- 主结果。
- 三宫路径或月日时路径。
- 完整结构化结果。
- 应用、请求、结果、知识和方法版本。
- 旧版迁移标记。

### 8.3 存储实现

建立独立存储端口与版本化集合，不把 `localStorage` 调用散落在 React 组件中。

允许使用命名空间明确的 `localStorage` v1 适配器；数据合同、容量错误和损坏数据必须 fail-closed。不得为了本轮引入重型状态管理库。

### 8.4 课例册功能

实现：

- 列表查看。
- 打开详情。
- 保存当前结果。
- 修改本地标题。
- 删除单条。
- 全部清除，必须二次确认。
- 导出全部课例 JSON。
- 导入兼容 JSON。

### 8.5 迁移

支持：

- R4/R5 月日时结果导入。
- R5 三数安全整数结果迁移为 R6 数字字符串与三宫结构。
- 缺失字段标记为“旧版数据”，不得猜造。
- 未知未来版本拒绝导入并说明原因。
- 原始导入对象不得被就地破坏。

## 10. 响应式应用结构

### 10.1 导航信息架构

一级入口：

```text
起课
课例册
六宫资料
方法说明
关于
```

### 10.2 桌面与大平板横屏

- 固定可收缩侧栏。
- 主区域最大宽度约束。
- 起课页采用双栏：左侧输入，右侧方法摘要/最近课例/生成后的主结果。
- 结果详情可使用右侧详情面板或主内容区域，不弹出狭窄手机式卡片。

### 10.3 平板竖屏

- 顶部紧凑导航或侧边 rail，按实际空间选择。
- 页面主体单列。
- 起课表单内部允许两列。
- 三宫路径横向排列。
- 技术详情默认折叠。

### 10.4 手机竖屏

- 顶部 app bar。
- 底部导航：`起课｜课例｜资料｜更多`。
- “方法说明”和“关于”进入“更多”。
- 起课方式使用可横向滚动的紧凑按钮组或两列网格，不使用四张高大的纵向 radio 卡。
- 主操作区避开底部导航和手势区。
- 主结果第一屏可见。

### 10.5 手机横屏

使用宽度、方向和可用高度共同判断，不只依赖宽度断点。

- 压缩顶部栏。
- 左侧方法/输入，右侧结果摘要或领域设置。
- 隐藏非必要长说明，保留可访问的展开入口。
- 不用固定底部大按钮占据大量高度。
- 左右安全区必须考虑摄像头开孔和圆角。

### 10.6 结果页层级

统一为：

1. 主结果。
2. 领域简要解释。
3. 三宫路径或月日时路径。
4. 现实核验与行动提示。
5. 保存到课例册和导出。
6. 来源与方法说明。
7. 技术详情。

三数路径展示：

```text
速喜 → 大安 → 小吉
第一宫  第二宫  第三宫 · 主判
```

传统路径展示：

```text
月宫 → 日宫 → 时宫 · 主判
```

主判不能只靠颜色表示，必须同时有文字或图标标记。

### 10.7 资料与详情

- 手机：详情采用全屏层，具有明确返回按钮。
- 桌面/横屏平板：优先右侧详情面板或并列布局。
- 弹层必须支持 Escape、Android 返回键、焦点恢复和滚动锁定。

## 12. Android 顶部、底部与 edge-to-edge

### 12.1 统一策略

明确采用 edge-to-edge：背景可延伸到系统栏后方，交互内容必须应用系统 inset。

不得继续同时依赖“整个 `.app-shell` 全局 padding”与不明确的原生窗口策略。

### 12.2 Web 层

保留：

```html
viewport-fit=cover
```

集中定义：

```css
--safe-top: env(safe-area-inset-top, 0px);
--safe-right: env(safe-area-inset-right, 0px);
--safe-bottom: env(safe-area-inset-bottom, 0px);
--safe-left: env(safe-area-inset-left, 0px);
```

只对真正需要避让的组件应用：

- 移动顶部栏。
- 桌面/移动侧栏顶部与底部。
- 移动底部导航。
- 粘性操作区。
- Toast。
- 全屏详情页。
- 横屏左右操作区域。

正文底部必须预留：

```text
底部导航高度 + safe-bottom + 内容间距
```

### 12.3 Android 原生层

按仓库实际 Capacitor/Android 版本使用官方支持的 edge-to-edge 与系统栏 API：

- 明确 WebView 是否绘制到状态栏和导航栏后方。
- 状态栏/导航栏背景与应用主题协调。
- 浅色模式使用深色系统图标，深色模式使用浅色系统图标。
- 三键导航与手势导航均不得遮挡点击目标。
- 保持 `adjustResize` 或等价 IME 适配，使软键盘出现时表单和底部操作仍可达。

不得把系统栏颜色和 Web 主题分别写死为互相冲突的值。

### 12.4 验收场景

- 手机竖屏状态栏。
- 手机竖屏底部手势区。
- 手机横屏左右安全区。
- 平板竖屏。
- 平板横屏。
- 浅色系统栏图标。
- 深色系统栏图标。
- 三键导航。
- 手势导航。
- 软键盘打开和关闭。
- 旋转屏幕后布局恢复。

## 13. Android 冷启动处理边界

本轮不再让 Codex反复自动调查或宣称修复用户设备黑屏。

最终交付只做：

1. `npm run mobile:sync`
2. 构建 debug APK。
3. 若仅检测到一台已授权 ADB 设备，执行 `adb install -r` 安装 APK。
4. 安装完成后不得脚本化启动应用，不得自动点击，不得继续冷启动测试。
5. 停止并报告：安装设备、包名、版本、APK 路径、提交 SHA、PR。
6. 等待用户从桌面图标主动打开并反馈。

若没有已授权设备：

- 不失败。
- 报告未安装原因。
- 保留 APK artifact 供用户手动安装。

保留现有设备测试代码可以，但 R6 不扩大其冷启动诊断范围，也不以其替代用户主动测试。

## 14. 无障碍

- 起课方式使用真实 button，配合 `aria-pressed` 或等价选择语义。
- 键盘可遍历全部导航和表单。
- 切换起课方式后焦点落到新输入区的合理位置。
- 动态结果使用克制的 `aria-live`。
- 折叠区提供明确的展开状态。
- 底部导航、抽屉和详情层具有可读名称。
- 所有主要点击目标满足移动端可操作尺寸。
- 不只通过颜色传递宫位、主判、安全状态或错误。

## 15. 测试与验证

- 传统月日时算法全量回归不变。
- 关系末宫解释安全措辞。
- 方法登记和 manifest fail-closed。
- 课例保存、读取、删除、清空、导入、导出与迁移。

- 深浅色主题持久化。
- 导航、详情层和 Android 返回键。

## 17. Git 与 PR 交付

1. 只创建一个实现分支：

```text
feature/r6-three-palace-archive-responsive-ui
```

2. 允许按逻辑提交，但最终只创建一个 R6 实现 PR。
3. 推送分支并创建/更新 PR 到 `main`。
4. 不自行合并实现 PR。
5. PR 描述必须报告：
   - 完成项。
   - 未完成项。
   - 已知问题。
   - 验证命令及结果。
   - 响应式截图路径或 artifact。
   - Android APK 路径/artifact。
   - 是否已安装到设备。
   - 明确写明：安装后等待用户主动冷启动测试。
   - 分支、head SHA、PR URL。
6. 最终回复保持简短，不复述长篇实现过程。

## 18. 完成判定

R6 只有同时满足以下条件才算完成：

- 当前时间入口与刷新动作合并。
- 三数输入无默认测试值并支持精确大整数。
- 三数结果拥有正式三宫合同，第三宫主判。
- 关系领域拥有安全的当前关系解释。
- 起课方法登记和 provenance 完整。
- 本地课例册可用且旧结果可迁移。
- 普通 UI 完整中文化。
- 桌面、手机、平板横竖屏均有结构性适配。
- Android 顶部、底部、左右 inset 和软键盘适配明确。
- APK 成功构建。
- 有设备时已安装但未由脚本自动启动，等待用户主动测试。
- CI、核心测试和有限截图 smoke 通过。
- PR 已创建，未自行合并。
